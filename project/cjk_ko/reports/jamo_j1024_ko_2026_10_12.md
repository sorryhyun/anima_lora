# J1024_ko — the J line to 1024 syllables and the 51 jamo — 2026-10-12

User 10-11: grow the J line in this line, as J128 → J256 (first J512, then
J1024 + every compat jamo). `jamo_j1024_ko` (`configs/jamo_j1024_ko.toml`):
jamo_j256_ko's 256 rows + the next 768 chatbot syllables by frequency (KS X
1001, H out; `corpus.py --jamo 1024` → `assets/jamo1024.json`), composed from
the jamo factors, and the 51 compat jamo (ㄱ … ㅣ) as free rows beside them
(`Jamo`'s own rows, below). jamo_j256_ko's recipe and data build, cold on
seed_1008: 56 steps a row, 60 200 steps, batch 4, lr 1e-3 cosine.

The 1024 cover 79 % of the chatbot lines' syllable tokens (J256: 54 %; H holds
20 %); the tail of the 768 reaches syllables the corpus holds once.

## Run

- Data: 107 501 items (tiers as J256_ko; each jamo 360–407 draws, a syllable's
  budget), 8.9 min CPU. Sheets by eye: the jamo draw in bubbles and on signs.
- Train: local GPU through the daemon, 419.8 min at 2.39 it/s. Loss by sixths
  0.098 → 0.091 → 0.092 → 0.088 → 0.086 → 0.075; row Δ norm peaks at 434
  (step ~12 k) and ends at 352 (max 426).
- Two false starts: the daemon's 120 s stall watchdog killed the TE encode
  (93 832 captions, silent ~20 min; resubmitted with `--stall-timeout 3600`,
  the cache resumed), then the latent encode died on SIGBUS — `/` full (the
  run's caches are 53 GB: TE 23, latents 24 as fp32 `.npy`, images 6.5). The
  run dir now lives on `/media/sorryhyun/new/anima_output/cjk_ko/jamo_j1024_ko`,
  symlinked from `output/cjk_ko/`.

## 2. Reading

- **Scale buys trained rows, not composition.** A syllable J1024 trains
  reads about as well as J256's own (17 / 61 vs 20 / 56), and J256's rows
  keep theirs with four times the rows beside them. H — every cell covered
  many times over now — does not move (8 → 7, jamo F1 0.46 → 0.43).
- **The J line's H gains were not size.** J128 → J256 moved H precision
  with the set and the steps doubled together; J256 → J256_ko (data only)
  was the larger step; J256_ko → J1024_ko (set and steps × 4) is flat. The
  zero-shot composition of b + C[cho, cls] + V + F has a ceiling that more
  rows of the same data do not lift. Candidates, none tested: the additive
  model cannot place a jamo by the syllable it sits in beyond the 3 `cls`
  (its size and position change with the vowel and the final); the data's
  faces / pose set the ceiling, as the J256_ko step suggests.
- **The strings are out of this data's reach** (1 → 0 / 27): phase-1 items
  are lone glyphs; the line habit and its cost are the dialogue warm's
  (`micro_2026_10_11.md`).
- **The jamo cost nothing** to put in the factor run.

## 3. Not separated

- The set and the total steps grow together (× 4), as J128 → J256.
- One render per item, seed 0: H's 8 vs 7 is noise; the per-group gains on
  trained rows (5 → 17 of 61) are not.

## 4. For the dialogue warm

J1024_ko is a better start than J256_ko: 79 % of the line's tokens are rows
it trained, and ㅋㅋ / ㅠㅠ have rows. What it does not give is any lift on a
syllable it did not train, so coverage is the lever: the ~130 chatbot
syllables left and H (held out only as the ruler).

## Code

- `reseed/jamo.py` `Jamo`: a trained row that is no syllable stays a free row
  of `raw` in the optimizer, the composition never writes it (`n_own`);
  `reseed/trainer.py` maps only the syllable rows, records
  `factor_own_rows`; `reseed/config.py` lets a factor config list compat
  jamo. `project/cjk_anima_reseed/tests/test_jamo.py::test_own_rows`.
- `corpus.py --jamo N`; `probes/micro_read.py --groups` (+ `H`, `jamo`, the
  J1024 arm); `probes/jamo_vl.py` `RENDER` reads the
  J1024 renders from `output/cjk_ko/micro_read/`.
