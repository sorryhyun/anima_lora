## Facts

### Design (written before the run)

- Question: do main and sub still read on the 11-22 data, and does `OCR2:` still answer empty
  on crops without a sub once no empty-sub row trains?
- Read: val main 500 and sub 500 against the parent's (same crops and targets), and the parent's
  292 val `sub_neg` crops (no longer in val) under `OCR2:`, share of empty answers.
- Bars: spread unknown (no seed twin). The numbers go beside the parent's; the user decides.
- Not read: the v7 gates, SFX or KO against v7.

### What changed from the parent

These change together; the run does not separate them.

- Data: the labels and loader of [`mainsub_labels_2026_11_22.md`](mainsub_labels_2026_11_22.md)
  and the agents' line breaks. Train 179,541 -> 164,553 rows (main 113,728, main_kozh 24,145,
  main_neg 3, sub 26,677, sub_neg 0).
- Code (uncommitted at the run): `finetune_vl16_lora.train_loss` works out indices, positions
  and masks on the CPU batch, so the forward and backward have no host sync; `vl16_compile`
  takes `cu_seqlens` on the CPU and drops the `interp_*` kwargs.
- The recipe is the parent's: stock base, seed 0, 1,000 steps. Command:
  `finetune_vl16_lora.py --run mainsub_1122_1446 --mainsub --steps 1000 --val_limit 500
  --tower_rank 64 --lm_full --ckpt_lm_only --compile` (`--ckpt_lm_only` implies `--grad_ckpt`).
- `mainsub_1122_1432` (step 275) and `mainsub_1122_1436` (last logged step 25) ran the
  unfixed code and were stopped on the way to this run; no checkpoint, no val.

### The code change's checks

- GPU utilisation / step time / power in profiler probes: 85.3 % / 812.6 ms / 258 W before
  (steps 40–70), 100 % / 691.5 ms / 292 W after (steps 5–8).
- Old against new loss on 3 micro-batches before any step: equal to 6 decimals. Relative
  gradient gap old/old then old/new: 1.57e-3, 4.1e-4; 3.08e-4, 3.16e-4; 2.54e-4, 4.68e-3.
  One old/old pair per batch; `lora_B` is zero there.
- Static read of the third batch's gap: no differing computation found. The tower's flash
  backward kernel has its template flags off (deterministic included, by upstream's layout).
  Not rerun.
- The log's `attention_mask` None recompile also appears in 7 runs of the old code.

## Interpretation

- `OCR2:` without negatives does not answer empty: it reads the main again, whole or in part.
  The data is the likely cause (no empty target trains); the code change touches no target.
  Negatives are needed before a longer main / sub run.
- Main is level with the parent on the paired rows; sub's 10-row gap has no spread to read it
  against.
- The gradient gap is probably the flash backward's accumulation order; one pair per batch
  does not settle it.
