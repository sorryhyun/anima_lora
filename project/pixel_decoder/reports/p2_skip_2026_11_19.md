# P2: why the ConvNeXt head sat at P1's level, and the no-skip head (2026-11-19)

Covers `convnext_1119_0835`'s stall, three probes on it (`ceiling_1119_0920`,
`overfit_1119_0924`, `overfit_lr1e3_1119_0925`) and the two training arms that followed
(`convnext_1119_0938`, `convnext_1119_0950`). Code and per-run records:
`bench/pixel_readout/` and its `README.md`; results under `bench/pixel_readout/results/` (local).

Setup shared by every run: anima-base, features = the input of `final_layer.linear` at σ 0.0577
(last σ of the 50-step shift-3 grid) from cached real latents, target = VAE decode of the clean
latent, PSNR against that target in dB. Held-out: 30 test images from 8 artists, 8 text images.
One seed everywhere; spread unknown.

## The stall

### Facts

- `convnext_1119_0835`: head = P1's ridge linear as a skip (LR 2e-5) + a residual path
  (`proj(f) + embed(x_t)` → 3 ConvNeXt blocks, layer scale γ 1e-6 → zero-init linear), LR 2e-4,
  batch 1, 4 updates per rollout, 3600 rollouts. Test 26.50 against P1's 26.28; text 21.58
  against 21.61.
- Its train loss (EMA) was 0.1005 at rollout 50 and 0.1059 at rollout 3600; train PSNR 24.3–25.0
  throughout.
- After 14,400 updates mean |out.weight| was 5.7e-3 and γ about 1e-3; the summed LR is 1.44.
- `gradprobe_1119_0914`: clip factor 1.000; at init the blocks, `proj` and `lat_embed` get zero
  gradient; pairwise cosine of per-image `out.weight` gradients 0.025 at init, 0.085 at the end
  (no null run).

### Interpretation

The run underfit its own training set, so data size and generalisation were not the limit. The
weights moved about 0.4 % of what the summed LR allows, which is what updates that change sign
from image to image give.

## ceiling_1119_0920 — is the target reachable from the features?

### Facts

Forward only, the 38 held-out images with P2's noise seeds. x̂0 = x_t − σ·v.

| | test (30) | text (8) |
|---|---|---|
| VAE(x_t) vs VAE(x0) | 30.73 | 27.08 |
| VAE(x̂0) vs VAE(x0) | 37.00 | 32.02 |
| P1 / `0835` vs VAE(x0) | 26.30 / 26.50 | 21.62 / 21.59 |
| P1 / `0835` vs VAE(x̂0) | 26.47 / 26.69 | 21.73 / 21.70 |

Latent RMSE to x0: x_t 0.068, x̂0 0.032 (latent RMS 0.63). Both VAE rows are above the `0835`
head on 38 / 38 images.

### Interpretation

FastFrames regresses the decode of the latent the DiT produced; this line regresses the decode
of the clean latent, which the features do not determine. That gap costs little here: the DiT's
own estimate decodes 10.5 dB above the head, and the decode of x_t, which the head receives as
an input, 4.2 dB above it. The target was not what held the head.

## overfit_1119_0924 / overfit_lr1e3_1119_0925 — can the head fit 16 images?

### Facts

Features, x_t and targets of 16 train images computed once (fixed noise); a fresh head per arm,
`0835`'s optimizer, 4000 updates at batch 1 (about 70 s per arm). On the 16 images: P1 25.71,
VAE(x_t) 31.07, VAE(x̂0) 37.05. PSNR at update 4000:

| arm | LR 2e-4: fit (16) / test (30) | LR 1e-3: fit / test |
|---|---|---|
| `parent`: P1 skip, out zero-init, γ 1e-6 | 31.51 / 25.67 | 40.48 / 23.79 |
| `open`: P1 skip, out zero-init, γ 1 | 35.05 / 24.66 | 47.53 / 25.21 |
| `noskip`: no skip, out default init, γ 1 | 30.83 / 27.16 | 39.42 / 26.74 |

- P1 on test is 26.30. Both skip arms' test falls below it as their fit rises.
- `noskip` test by update, LR 2e-4: 24.05 @ 500, 26.94 @ 2000, 27.16 @ 4000.
- Updates clipped at norm 1.0: `noskip` 413 (LR 2e-4) and 500 (LR 1e-3) of 4000; skip arms 0–1.
- Claude's prediction before the LR 1e-3 run was that a higher LR would not help; on 16 images
  every arm fit faster at 1e-3.

### Interpretation

The head as built can be trained, zero init and layer scale included. With the skip, what the
residual path learns is specific to the fit images. Without it, 16 images were enough to put
test above `0835`'s full run. A reading: the ridge solution takes everything linear in the
features, and what is left for the residual path points a different way on each image; a head
that has to learn the linear part itself gets a gradient the images share, and the features it
builds for that carry over to the rest. Fit values above 37 are past the DiT's own x̂0 and can
only be the fixed noise draws memorised. The probe does not separate the skip from the out init
and γ.

## convnext_1119_0938 — the no-skip head on the full train set

### Facts

Parent `0835`, `--no_skip --ls_init 1.0`; LR 2e-4, batch 1, data, order, noise seeds and schedule
as the parent. 25 min, 0.42 s / rollout, 29.7M parameters.

| | test (30) | text (8) |
|---|---|---|
| P1 linear | 26.28 | 21.61 |
| `0835` final | 26.50 | 21.58 |
| `0938`, rollout 600 / 1200 / 1800 / 2400 / 3000 | 25.69 / 29.39 / 31.01 / 32.21 / 32.64 | 22.63 / 25.14 / 26.21 / 26.99 / 27.36 |
| `0938`, rollout 3600 (final) | 32.93 | 27.45 |

- Per image, head − P1: test +5.04 … +8.27 (30 / 30 up), text +4.95 … +6.66 (8 / 8 up).
- Train PSNR (EMA) 30.7 at rollout 1950.
- Claude's read (labelled; 2× crops of sheets 00, 08 and text 02, columns VAE | P1 | head): the
  16-px grid and the flat-region grain are gone and outlines are continuous; against the VAE the
  head is a little softer, thin lines waver slightly (bikini strings, sheet 08), and small
  balloon text is legible with softer strokes.
- The user's read: pending.

### Interpretation

**Dropping the P1 skip is what made P2 train: +6.4 dB on test and +5.9 dB on text over `0835`
with the data, LR, batch and budget unchanged.** The head is past the decode of x_t (30.73) and
4.1 dB under the decode of the DiT's own x̂0 (37.00). The curve was still rising when the cosine
schedule ended (+0.29 dB over the last 600 rollouts), so the run length, not the head, set where
it stopped. FastFrames' head has no skip, zero init or layer scale; those were this line's
additions.

## convnext_1119_0950 — gradient over 4 rollouts at LR 1e-3

### Facts

Parent `0938`, `--accum 4 --opt_steps 1 --lr 1e-3` (the user's arm): each update averages the
gradient over the last 4 rollouts, one update per rollout. Same rollout budget, head compute and
uses per rollout; 3600 updates against 14,400; summed LR 1.25×. The run does not separate the
three changes.

Result: running.
