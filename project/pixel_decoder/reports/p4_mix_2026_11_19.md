# P4 mix: one head over the base and turbo decode points, and the release head `mixr_1119_1455` (2026-11-19)

The user's question: can one head be trained for the standard sampler, Spectrum and turbo at
once, on the same data? The per-point heads of `p4_t2_2026_11_19.md` were each read off their own
point only; no head trained on both points had been run. `mix_1119_1415` is the fixed-point arm,
`mixr_1119_1455` the release head with the base σ drawn over a range. The last section measures
the head's tone against the VAE (the user's read: a systematic tone difference). The 20-step
and 50-step crops were read by Claude on the user's word.

## Code

### Facts

`convnext_head.py --points SIGMA[:adapter] …`: decode points for one head, taken in turn per
rollout (`points[r % n]`). A bare σ runs the base DiT; `σ:adapter` runs with `--adapter` on. The
adapter is switched per rollout with `network.set_enabled` (off = every LoRA module returns its
`org_forward`). Held-out features, evals, sheets and metrics are per point (`<point>.<set>`); a
run without `--points` keeps its keys. `LO-HI` draws σ uniformly per rollout (own seeded stream)
and is evaluated at LO, the midpoint and HI.

### Interpretation

mixed run's points are the T2 point and the base DiT. The head's compile falls back to eager
after 12 shapes in every run of the replay recipe; it costs speed only and is listed in the
plan's open items.

### Interpretation

On turbo the mix head sits 0.25 dB (colour) and 0.17 dB (mono) under the T2 head, on every one of
the 32 images. With no run-to-run spread the size cannot be called a loss or a tie from the
number; the sign is the same on all images, which a paired read on identical renders would show
for a real but small cost of sharing the head. The two heads had the same number of σ 0.5
rollouts (500), so the gap is not exposure at that point; the mix head's cosine schedule ran over
twice the updates.

On base renders the mix head is 3.85 / 2.52 dB over the pagemix head. That reference never
trained at σ 0.10, so the gain is mostly training at the point being read, not a gain from
mixing; what the base read does show is that sharing the head with the turbo point did not keep
it from reaching 32.91 / 25.65 at σ 0.10. Whether a base-only σ 0.10 head would be higher is the
unrun reference.

Both eval curves were still rising at rollout 1,000 (base test +0.21, adapter test +0.28 over
the last 200), as `t2a_1119_1337`'s was at 500.

range's extra gain at σ 0.136 over its gain at σ 0.10 is 0.3 dB on colour.

### Interpretation

The head is darker than the VAE where the image is textured and level where it is flat. Over a
whole image the gap is under one 8-bit level; in screentone-like blocks of mono renders it is
about 2.5 levels in linear light on the base DiT and 1 level on turbo, with over 90 % of those
blocks on the dark side, so it is a bias and not scatter. The direction matches the user's read.

Two parts add up to it. The head keeps 90 – 96 % of the VAE's high-frequency energy; a pattern
smoothed in code values keeps its code mean but averages darker in linear light (the last column
of the block table is that effect at full smoothing), and the measured linear-light shift is
roughly a tenth of it. The rest is a shift of the code mean itself, −0.7 … −1.0 levels on mid
and light textured blocks of mono renders, which smoothing alone does not produce; the L1 + MSE
loss is computed on code values and has no term on local tone.

On real pages read teacher-forced the same blocks shift by half a level, so the larger numbers
belong to generated renders; that comparison is against VAE(x0) and does not separate the head
from the DiT's x̂0.

A fix belongs to P5 (pixel losses on the head): a low-frequency tone term in linear light, or a
loss that restores the dots themselves.
