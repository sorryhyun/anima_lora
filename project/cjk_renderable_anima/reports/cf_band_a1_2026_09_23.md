# cf_band A.1 — the ceiling map by glyph px, font weight, count and layout (2026-09-23)

`plan_band.md` Stage A.1: EN text on the base model (no rows, no training),
`cf_sense` with the per-item px / pinned font / layout / text-shape knobs.
The number read per cell is the caption's leverage `move` on a B-rendered
input, mean over 16 pairs, at σ 0.35 / 0.4 / 0.5 / 0.6 / 0.7 / 0.8 / 0.9;
**peak** = argmax σ, **live** = the σ where mean move ≥ 0.1.

```
… --stage cf_sense --arm rows --data_tag step1_0921 --arm_tag s30k --cf_lang en \
  --cf_pairs 16 --cf_per_pair 6 --cf_glyph_px 24,32,48,64,96,128 \
  --cf_t 0.35,0.4,0.5,0.6,0.7,0.8,0.9 --eval_tag a1 \
  --cf_layout {flat|bubble|grid} --cf_font …/NotoSerifCJK-{Regular|Light|Black}.ttc \
  --cf_text {letter|string2}
```

Ten launches (five runs × two text shapes), 1.7 min a letter run and 3.2 min
a string run; outputs under
`output/wake_probe/rows_step1_0921_s30k/cf_sense_en_<layout>_<text>_<font>_a1/`.
The per-cell table with rendered widths is in the same directory's
`cf_sense.md`; the compact form below is from the `.pt` files (rendered
per-glyph width = box width / glyphs, box height, ink per glyph in cells²).

## Which cells are real

The asked px is the font size. A single letter renders at it (box height ≈
px). A two-word string (11 letters) at font 64+ is **wider than the 512
canvas**: the box caps at 47 px per glyph and the leverage collapses (0.07 at
96, 0.05 at 128) — those cells are cropped strings, not large strings, and
are dropped. The bubble string cells are all one cell: the ellipse fit caps
the string at ≈ 27 px per glyph whatever px is asked. The grid string cells
are drawn at 12–24 px (the 3 × 3 cell cannot hold more); they are the
low-px end of the curve, binned by the px actually drawn.

Valid: letter × {24 … 128} on every layout and font; string × {24, 32, 48}
flat (per-glyph width 19 / 25 / 37 px); string × bubble = one 27 px cell;
grid string = 13–20 px.

## 1. Size (run 1, flat, Regular)

| font px | letter peak | letter live | string peak | string live |
|---|---|---|---|---|
| 24 | 0.5 | 0.35–0.7 | 0.6 | 0.4–0.7 |
| 32 | 0.5 | 0.4–0.7 | 0.6 | 0.5–0.7 |
| 48 | 0.6 | 0.5–0.7 | 0.7 | 0.6–0.8 |
| 64 | 0.7 | 0.6–0.8 | (cropped) | |
| 96 | 0.7 (0.15 vs 0.14 at 0.8) | 0.7–0.8 | | |
| 128 | 0.8 | 0.8 | | |

Peak σ is monotone in px with no plateau: one grid step per ≈ doubling of
px. The 24 px letter is still live at σ 0.35 (0.17), so its floor is below
the grid. A.0's rebin (40–60 px → 0.7, 60–100 → 0.8) sat one step higher
because its px was the ellipse-fitted box, not the font size; the ordering
is the same.

**Count (H-count at the ceiling): a string peaks 0.1 σ above a single letter
at the same font size**, at every valid px (24, 32, 48), on all three fonts.
So at fixed glyph size a multi-glyph one-token string wants a *higher* σ than
a single glyph, not a lower one — the training reads that put pieces at
0.5–0.7 and singles at 0.7–0.9 were size (35 px pieces vs 50–200 px singles),
with count pulling the other way.

## 2. Ink (runs 2–3, flat, Light vs Black)

Letter cells, peak / live:

| font px | Light (ink) | Regular (ink) | Black (ink) |
|---|---|---|---|
| 24 | 0.5 / 0.35–0.7 (1.4) | 0.5 / 0.35–0.7 (1.4) | 0.5 / 0.35–0.7 (2.1) |
| 32 | 0.5 / 0.4–0.7 (2.3) | 0.5 / 0.4–0.7 (2.4) | 0.5 / 0.4–0.8 (3.7) |
| 48 | 0.6 / 0.5–0.7 (5.1) | 0.6 / 0.5–0.7 (5.4) | 0.6 / 0.6–0.7 (8.1) |
| 64 | 0.7 / 0.6–0.8 (8.1) | 0.7 / 0.6–0.8 (8.6) | 0.7 / 0.6–0.8 (14.3) |
| 96 | 0.7 / 0.7–0.8 (19.0) | 0.7 / 0.7–0.8 (20.5) | **0.8** / 0.7–0.8 (31.7) |
| 128 | 0.8 / 0.8 (33.1) | 0.8 / 0.8 (34.4) | 0.8 / 0.8 (53.8) |

Light and Regular are the same font on this ruler (ink within 5 %, every
number within 0.02). Black carries 1.5–1.7 × the ink and moves the peak at
**one** px — 96, where Regular's own 0.7 / 0.8 are 0.15 / 0.14 — and moves
the live band's edge by one step at 32 (up to 0.8) and 48 (floor 0.6, not
0.5). String cells agree: Black 48 px peaks 0.7 like Light, Black's floor is
one step higher at 32–48.

Ink is not the key: Black 48 px (ink 8.1) peaks 0.6 while Regular 64 px
(ink 8.6) peaks 0.7; Black 64 (14) and Regular 96 (20) both peak 0.7. Ink
adds a shift of order half a grid step on top of px. **Stage C's gate** as
written (Light and Black peak at the same σ at every px) trips on the 96 px
tie-break only; read as a ≥ 0.1 effect it does not. Kanji take the kana band
for their px unless a training read says otherwise; the ≈ 0.05 σ ink
contribution is not worth two arms.

## 3. Layout (runs 4–5 vs run 1, Regular)

| font px | flat letter | ellipse letter | grid letter |
|---|---|---|---|
| 24 | 0.5 / 0.35–0.7 | 0.5 / 0.35–0.7 | 0.5 / 0.4–0.7 |
| 32 | 0.5 / 0.4–0.7 | 0.5 / 0.4–0.7 | 0.6 / 0.6–0.7 |
| 48 | 0.6 / 0.5–0.7 | 0.6 / 0.5–0.7 | **0.8** / 0.7–0.8 |
| 64 | 0.7 / 0.6–0.8 | 0.7 / 0.6–0.7 | **0.8** / 0.8 |
| 96 | 0.7 / 0.7–0.8 | 0.7 / 0.7–0.8 | **0.8** / 0.8 |
| 128 | 0.8 / 0.8 | 0.8 / 0.8 | **0.9** / 0.9 |

**Ellipse = flat** to the second decimal at every px (A.0's read, now on
pinned font and 16 pairs per cell). The ellipse string cell (27 px per glyph,
every asked px) peaks 0.6 with live 0.5–0.7 — the flat 32 px string.

**The grid moves the peak up by 0.1–0.2 σ from 32 px on** and halves the
leverage (peak move 0.15–0.19 vs 0.24–0.32 flat): the centre cell's caption
is one of nine in the grid caption, and the eight neighbours are legible
glyphs the model reads at the same σ. So a grid cell wants a band above a
flat or bubble glyph of the same size — H-layout holds for the grid, not for
the bubble. Grid strings at 13–20 px per glyph peak 0.35–0.5, the low-px end
of the size curve, nothing layout-specific.

## A.2 — the small end, 12–32 px, σ 0.15–0.6 (same day)

Scope change: the pack must serve downstream LoRA training on real images,
which carry 16 px glyphs. Four launches, px {12, 16, 20, 24, 32} per item,
σ {0.15, 0.2, 0.25, 0.3, 0.35, 0.4, 0.5, 0.6}, Regular, `--eval_tag a2`.
Box widths below 32 px are the reader's 4-cell minimum, so per-glyph width
is read off the string cells (11 / 14 / 16 / 19 / 25 px at 12–32).

| font px | flat letter peak / live (max move) | flat string peak / live (max) | grid letter peak / live (max) | grid string peak / live |
|---|---|---|---|---|
| 12 | 0.4 / 0.2–0.6 (0.36) | 0.35 / 0.2–0.6 (0.22) | 0.3 / 0.3–0.5 (0.15) | 0.3 / 0.3–0.5 |
| 16 | 0.4 / 0.2–0.6 (0.41) | 0.4 / 0.25–0.6 (0.28) | 0.5 / 0.4–0.6 (0.21) | 0.4 / 0.35–0.6 |
| 20 | 0.5 / 0.25–0.6 (0.35) | 0.5 / 0.35–0.6 (0.27) | 0.6 / 0.4–0.6 (0.18) | 0.5 / 0.4–0.6 |
| 24 | 0.5 / 0.35–0.6 (0.30) | 0.6 / 0.4–0.6 (0.26) | 0.5 / 0.5–0.6 (0.21) | 0.6 / 0.5–0.6 |
| 32 | 0.5 / 0.4–0.6 (0.23) | 0.6 / 0.5–0.6 (0.25) | 0.6 / 0.6 (0.17) | – |

- **16 px is not hard for the caption at the ceiling.** A 12–16 px letter
  carries *more* leverage (0.36–0.41) than a 24 px one (0.30) or a 48 px one
  (0.27), over a band twice as wide (0.2–0.6). What moves with px is where
  the band sits, not whether the caption can decide the glyph. A 16 px
  string peaks at 0.4 with live 0.25–0.6 (0.28).
- The size curve continues monotone below 24: peak 0.4 at 12–16, 0.5 at
  20–32 (letters); strings one step above at 24–32 as in A.1, level with
  letters at 12–16.
- **Grid: +0.1 σ and half the leverage again**, down to 16 px; at 12 px the
  grid cell is at the floor (0.15 max move).
- Order leverage for a 12–16 px string (three-word permutation) peaks at
  0.3–0.5 with 0.26–0.30, the strongest order read in the line.

Training band for a 16 px multi-glyph scene item: **0.25–0.6**, centre 0.4
(bubble = flat). That is below `band2`'s 0.35–0.7 (sentence items at 25–32
px, whose ceiling is 0.4–0.6): a data dir built with `--scene_min_glyph 16`
mixes 16 and 30 px text and wants either a wider band (0.25–0.7) or the
per-item band from the record's `ink` / `box` fields.

## What this fixes in `plan_band.md`

- **H-size holds, H-ink is a half-step, H-layout holds for grid only,
  H-count holds with the sign reversed** (string above letter by 0.1 σ at
  fixed size). The per-item band is keyed on rendered glyph px, plus one
  step for a grid cell.
- **Stage C does not run** on this evidence (§ 2).
- **Predictions for Stage B at the ceiling**: S singles at 48 px in a bubble
  → peak 0.6, live 0.5–0.7, so `bs_lo` (0.5–0.7) over `bs_hi` (0.7–0.9);
  M pieces at 35 px (font 32–48, 2–4 glyphs) → peak 0.6–0.7, live 0.5–0.8,
  consistent with the training order 0.5–0.7 > 0.6–0.8 > 0.7–0.9
  (`micro_cf_0922`). Grid cells at 85–200 px → peak 0.8–0.9, live 0.8–0.9:
  step 1a's grid half is banded right at 0.7–0.9 and would not do better
  lower (B.3's question, answered at the ceiling).
- **The recipe's step 1a mixes two regimes that want different bands** —
  scene singles at ≈ 50 px (live 0.5–0.7) and grid cells at 85–200 px (live
  0.8–0.9) — under one 0.7–0.9 band that is the top edge of the first and
  the bottom edge of the second. Stage D's per-item band is the fix if B.1
  confirms the scene half prefers 0.5–0.7.
