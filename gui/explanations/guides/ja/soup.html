Soup

Uncond-init ΔW スープ — 新しいアダプタファミリーではなく、データセットの任意のグロブ(glob)スライスに対する LoRA の品質と堅牢性を高めるレシピです。出力は通常どおりベイク可能な LoRA です (output/ckpt/anima_soup_<slug>.safetensors)。

3 つのフェーズ。 (1) 希釈プール(diluted pool)(フォームのプールパターン、デフォルト * = データセット全体；ファインチューニング対象は常に統合されます)に対して短く行う caption_dropout_rate 1.0 の uncond インタートレイン — 同じプールを使うすべてのスープで再利用される、共有された決定論的チェックポイントです。(2) その uncond チェックポイントから初期化した、パスパターン画像に対するシードごとの N 回のファインチューニング。(3) それらのファインチューニングを network_dim に SVD で切り詰めた正確な ΔW スープ。

得られるもの。 品質向上に加えてシードくじ保険: 3 回分のファインチューニングをスープ化すると、おおよそ最良の単一素材の水準に到達するため、悪いシードを引いてもランを台無しにしなくなります。ランク 16 の SVD 切り詰めはほぼ無料です(エネルギー保持率 ~99.9%)。記憶(memorization)問題の解決策ではありません。

要件。 通常の LoRA チェックポイントのみに対応します(Hydra やその他の非プレーン LoRA のキー構造は拒否されます)。パスパターンは必須です — fnmatch グロブ(| で複数パターンを区切ります、例: sincos/* や art_a/*|art_b/*)で、各画像のパス(サブセットの image_dir を基準とした相対パス)と照合されます。以前の単一アーティスト対象(target)を置き換えるものです。uncond プールはファインチューニング対象より広い必要があります。そうすることで対象が少数派になります(デフォルトの * プールはこれを保証します)。プール・スープ数(num_soup)・ランクの各項目(下の[soup]セクション)は妥当なデフォルト値を持っているので、理由がわからなければそのままにしておいてください。1 つのデーモンコマンドジョブとして実行されます(パイプラインが自身で train.py の各フェーズを駆動します)。docs/ と scripts/soup/ を参照してください。
