# 부록 2. LoRA soup과 merge의 측정

`02_soup_merge.md` 본문의 근거가 된 측정입니다.

## A2.1 같은 시드 두 런이 갈라지는 이유

`02_soup_merge.md` §1.2의 같은 명령 두 런(1200 step, ΔW 코사인 0.41)에서 시드로 고정되지 않는 차이는 두
군데 있습니다.

- **attention backward의 누적 순서.** FlashAttention backward는 dK, dV를 atomic add로 누적하므로 더하는 순서가
  런마다 다릅니다. 여기서 생기는 step당 약 1e-4의 차이를 학습이 1200 step 동안 키웁니다. LoRA 경로의 나머지(GEMM,
  norm, optimizer)는 결정적입니다.
- **compile한 graph의 반올림.** compile한 graph는 eager와 bf16 반올림이 다르고, graph가 바뀌면 또 달라집니다.
  가중치와 데이터가 같고 graph만 다른 두 설정이 step 1 loss부터 0.35949와 0.35962로 갈렸는데, eager에서는 두 설정이
  0.350093으로 같았습니다. 생성에서도 compile한 렌더와 eager 렌더는 구도가 같고 머리카락, 무늬 같은 세부가
  다릅니다(두 측정 모두 MOSS-Image).

결정적인 attention backward를 쓰고 PyTorch의 결정적 알고리즘을 켜면 두 런의 체크포인트가 bit 단위로
같아집니다(텐서 1092개 중 차이 0). 대신 처리량이 약 33% 줄고, 같은 GPU, 드라이버, 라이브러리에서만 성립합니다.
그리고 결정적 설정이 주는 것은 재현성뿐입니다. 설정 하나를 바꾼 런 쌍의 ΔW 코사인은 결정적 설정에서도 0.02 안에서
같았습니다(0.305 vs 0.320, 0.396 vs 0.402). 1e-4짜리 하드웨어 차이든 실제 설정 차이든 학습을 거치면 비슷한
수준(약 0.4)까지 갈라지는 거죠. 그래서 ΔW 코사인으로는 두 런이 어느 블록에서 갈라졌는지는 볼 수 있지만, 차이가
얼마나 큰지는 잴 수 없습니다.

## A2.3 rank truncation에서 남는 에너지

평균 ΔW를 rank r로 잘랐을 때 모듈별로 남은 에너지 비율입니다.

| soup | 재료 | 자른 rank | retained energy 평균 | 최솟값 |
|---|---|---|---|---|
| 그룹 하나, uncond init, 시드 3개 | rank 16 | 16 | 99.87 % | 96.8 % |
| 그룹 8개 각각, 시드 3개 (재료 cos 0.19–0.23) | rank 32 | 32 | 99.70–99.82 % | 90.4–94.2 % |
| 그룹 8개 각각, 시드 3개 (재료 cos 0.06–0.09) | rank 32 | 32 | 98.59–99.18 % | 92.8–95.7 % |

재료끼리 덜 겹칠수록 평균 ΔW의 실제 rank가 커지고, 같은 rank로 자를 때 잃는 에너지도 늘어납니다. 시드만 다른
재료는 이 손실이 1–2 % 안입니다.

## A2.5 merge가 정확한지 확인

합친 LoRA가 정확히 "0.342 × 8개 soup의 합 + modulation 층 평균"인지 Gram trace로 쟀습니다(‖X − Y‖² = ‖X‖² +
‖Y‖² − 2⟨X, Y⟩, ⟨UD, U′D′⟩ = tr((UᵀU′)(D′Dᵀ)), ΔW를 직접 만들지 않으므로 CPU에서 잽니다). 상대 Frobenius 오차는
일반 모듈 1.7e-3(bf16 반올림), modulation 층 1.4e-8이었습니다.
