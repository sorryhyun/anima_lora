# Anima LoRA ガイドブック

**Anima LoRA** 学習/推論パイプラインの日本語ガイドです。インストール → データセット → 前処理 → 学習 → 推論 → ComfyUI 配布の順に進めます。Windows 初心者を対象に **GUI の使用を前提**として書かれており、ターミナルのコマンドはすべて [付録 A](#付録-a-cli-の使い方) にまとめてあります。WSL・Linux・学習最適化については他のドキュメントを参照してください。

## 1. システム要件

| 項目 | 最小 | 推奨 |
|---|---|---|
| GPU | **RTX 3060 以上**（20xx シリーズ以下は使用不可） | VRAM 16 GB 以上 |
| システム RAM | 16 GB | 32 GB 以上 |
| ディスク | 60 GB の空き | 200 GB 以上（キャッシュ + 出力の蓄積用） |
| OS | Windows 11 / Ubuntu 22.04+ | Ubuntu 24.04 |
| Python | **必ず 3.13** | - |
| NVIDIA ドライバ | **595 以上**（CUDA 13.x の要件） | - |

## 2. インストール

PowerShell に以下の 1 行を貼り付けてください。`uv`・CUDA 13.2・Python 3.13・依存関係をすべて自動でインストールし、完了すると **GUI を自動的に開きます**。

```powershell
irm https://raw.githubusercontent.com/sorryhyun/anima_lora/main/install.ps1 | iex
```

- インストール先は `.\anima_lora\` です（`$env:ANIMA_DIR` で変更、`$env:ANIMA_VERSION='v1.4.0'` でバージョン固定が可能）。
- **再起動を求められたら**（CUDA インストール後によくあります）、再起動してから同じコマンドを再実行してください — 続きから進みます。
- 次回以降はデスクトップの **「Anima LoRA GUI」** ショートカットから起動します。

インストールが終わったら、GUI で **§3 → §4 → §5** の順に進めてください。

> 自分で `git clone` したい場合や自動インストールが失敗した場合は [付録 B](#付録-b-手動インストール-uv--git) / [付録 C](#付録-c-cuda-の手動インストール) を参照してください。

## 3. Hugging Face サインインとモデルのダウンロード

### 3.1 サインイン

1. <https://huggingface.co/settings/tokens> で **read** 権限のトークンを発行します。
2. GUI の **Hugging Face サインイン** 欄にトークンを貼り付けます。

トークンは Hugging Face 標準のキャッシュに保存されるため、GUI と CLI が同じ認証情報を共有します。

### 3.2 モデルのダウンロード

GUI の **Models** ダイアログのボタン 1 つで以下の 3 つをダウンロードします。

| ファイル | パス |
|---|---|
| Anima DiT（拡散モデル本体） | `models/diffusion_models/anima-base-v1.0.safetensors` |
| Qwen3 0.6B テキストエンコーダー | `models/text_encoders/qwen_3_06b_base.safetensors` |
| QwenImage VAE | `models/vae/qwen_image_vae.safetensors` |

**SAM3** と **MIT** のチェックポイントも併せて取得されます。この 2 つはオプション機能であるマスクド損失（[§7.4](#74-マスクド損失テキストバブルの除外)）でのみ使用されます。

> **SAM3 はゲート付き（gated）モデルです。** <https://huggingface.co/facebook/sam3> で **Request access** をクリックし、承認を待つ必要があります（数分〜数日）。承認前は 403 エラーで失敗します。主要な 3 モデルはゲート付きでは *なく*、SAM3 が失敗してもダウンロードは続行されるため、承認待ちの間も学習を開始できます。
>
> ダウンロードが頻繁に途切れる場合は [付録 A](#付録-a-cli-の使い方) の個別ターゲットで分けて取得してください。

## 4. データセットの準備

*画像 + 同名の `.txt` キャプションサイドカー* という構成です。元画像は `image_dataset/` に置きます（サブフォルダは自由）。

```
image_dataset/
├─ 00001.png
├─ 00001.txt
├─ 00002.jpg
├─ 00002.txt
└─ subfolder/
   ├─ 00010.webp
   └─ 00010.txt
```

### 4.1 キャプション作成のヒント

Anima の公式ガイドラインに従い、タグの順序は常に `[meta] [character] [series] [artist] [general]` です。

```
absurdres, safe, 1girl, chitanda eru, hyouka, @channel (caststation), full body, serafuku, She is saying hi.
```

- `absurdres`、`highres`、`masterpiece` などの**クオリティタグは書かないか、最小限に**留めるほうが結果が良くなります（今後正式リリースされる mod guidance を使えば、まったく書く必要がなくなります）。
- **手作業でキャプションを書きたくない場合**は、GUI の **Dataset** タブで画像を選んで **Autotag** をクリックすると、内蔵の **Anima Tagger** が正しい順序でキャプションを埋めてくれます（[§6.3](#63-dataset-タブ-autotag--grouping)）。ただし結果をそのまま使わず — 特にキャラクター/シリーズ/アーティスト名は学習前に確認してください。

## 5. 前処理

学習速度と VRAM を最適化するため、**リサイズ → VAE 潜在変数キャッシング → テキスト埋め込みキャッシング**を事前に実行します。GUI の **Preprocess** タブでボタン 1 つで 3 ステップすべてを実行できます。

| ステップ | 内容 | 出力先 |
|---|---|---|
| リサイズ | VAE が要求するピクセル整列に合わせてサイズ調整、画像ごとに固定トークンバケットを割り当て、小さすぎる画像（既定では 0.5 MP 未満）を除外 | `post_image_dataset/resized/` |
| VAE 潜在変数キャッシング | VAE を一度だけ実行して保存 → 学習中に VAE を GPU に載せない | `post_image_dataset/lora/{stem}_{WxH}_anima.npz` |
| テキスト埋め込みキャッシング | Qwen3 0.6B + LLM アダプターの出力を事前計算（キャプションのシャッフルバリアントを含む） | `post_image_dataset/lora/{stem}_anima_te.safetensors` |

PE ビジョン特徴量のキャッシング（`{stem}_anima_pe.safetensors`）は CMMD 検証にのみ必要なオプションのステップです。

> **⚠️ キャッシュは再利用され、自動的に削除されることは絶対にありません。**
> 前処理を再実行しても既存の `.npz` / `_te.safetensors` / `_pe.safetensors` は上書きも削除もされず、**不足している項目だけ**が新たに処理されます。そのため再実行は高速で、途中で中断しても安全です。
>
> - **画像を追加した場合** → そのまま再実行すれば OK です。
> - **キャプションを修正した場合**やトークナイザー/リサイズのオプションを変更した場合 → 単純な再実行では反映されません。キャッシュフォルダ（`post_image_dataset/lora/`）を手動で削除してから再実行してください。

## 6. GUI の使い方

設定の編集、データセットの閲覧、前処理、学習の実行/監視、LoRA のマージを 1 つのウィンドウで行えます。

- **学習設定 (Training Config)**: バリアントのドロップダウン（推奨 `tlora`）と **Hardware** ドロップダウン（Default 16GB+ / Low VRAM 8GB）を選び、学習キーを編集してそのまま学習を開始します。データ範囲（`sample_ratio`、`artists_shard`）は基本 (Basic) セクションの通常の入力フィールドです。
- **前処理 (Preprocess)**: リサイズ + VAE + テキスト埋め込みキャッシングを一括実行。
- **データセット (Dataset)**: 画像/キャプションのプレビューと編集、Autotag、Grouping（[§6.3](#63-dataset-タブ-autotag--grouping)）。
- **マージ (Merge)**: 学習済み LoRA をベース DiT に焼き込み、ComfyUI 単体チェックポイントとして保存（基本 LoRA / OrthoLoRA / T-LoRA のみ対応）。

GUI は `configs/gui-methods/<variant>.toml`（バリアントごとの単一ファイル）を読み込み、内部で `train.py` を呼び出すため、同じ設定を CLI からも再現できます（[付録 A](#付録-a-cli-の使い方)）。

### 6.1 フォームの編集と保存の動作

学習/前処理のサブプロセスはディスク上の variant TOML を読み直します。そのためフォームを編集しただけで保存しないと反映されませんが、GUI は次の 2 つでこれを扱います。

- **変更検知**: フィールドや `+ Extra args` を編集すると `Save` ボタンがオレンジの `Save *` に変わります — *画面とディスクが異なる*という合図です。
- **自動保存**: 保存を忘れて `Train` / `Preprocess` を押しても、その時点のフォーム値がまず variant ファイルに書き込まれてから実行されます。つまり **画面に見えている値がそのまま学習に使われます**。（`Test` は最後のチェックポイントで推論するため自動保存の対象外です。）

> 編集を取り消したい場合は、variant を別のものに切り替えて戻してください — ディスクから再読み込みされ、編集は破棄されます。

### 6.2 学習の停止と GUI のクローズ

学習は GUI ウィンドウの中ではなく、`train.py` を分離されたプロセスとして実行するバックグラウンドの **学習デーモン** で進行します。

- **`Stop` ボタンは現在のジョブのみを中断します。** デーモンは起動したままキューの次のジョブへ進みます。
- **GUI を閉じても学習は止まりません。** 再度開くと実行中のジョブに自動的に再接続され（`Re-attached to running job …`）、進捗バーとログがリアルタイムで続きます。一晩かけて回す長時間の学習に便利です。
- 例外として **`Test` と `Preprocess` はウィンドウ内のサブプロセス**なので、GUI を閉じるとキャンセルされます。
- 学習を完全に止めて GPU まで解放するには、CLI の `make daemon-terminate` が必要です（[付録 A](#付録-a-cli-の使い方)）。

### 6.3 Dataset タブ: Autotag & Grouping

**Autotag — キャプションの自動生成。** 画像を選んで **Autotag** をクリックすると、**Anima Tagger** が `[meta] [character] [series] [artist] [general]` の順にタグを予測してキャプション欄を埋めます。初回のクリック時のみモデルのダウンロードで時間がかかり、以降はモデルがバックグラウンドに残るためほぼ即座に処理されます。他の GPU ジョブを開始する前に、タガーは自動的に GPU メモリを解放します。

**Grouping — 類似画像のクラスタリング。** **Group** をクリックすると、ほぼ同一の画像や同じシーン/キャラクターの画像をクラスタリングし、リスト上で折りたためる **緑色のグループヘッダー** にまとめます。重複の削除や、コンセプトごとの比重調整に使います。

- ファイル名やキャプションではなく *視覚的な内容* で比較し、グループは **最上位フォルダ単位**（アーティスト/キャラクターのバケット）で計算されるため、異なるフォルダの画像が混ざることはありません。
- キャッシュされた特徴量を再利用するため、画像を追加した後にいつ再クリックしても負担は小さいです。

> どちらの機能も **元の** `image_dataset/` 画像に対して動作し、前処理キャッシュには影響しません — 前処理の *前* に実行してキャプションを整理してください。

## 7. 学習

設定のマージ順序は `configs/base.toml → configs/presets.toml[<preset>] → configs/methods/<method>.toml → CLI args` で、**メソッド設定がプリセット設定を上書きします**。

最もおすすめの出発点は **OrthoLoRA + T-LoRA（`tlora` バリアント）** です — 安定性・ディテール・スタイル保持のバランスが最も良く、通常のキャラクター/スタイル LoRA にそのまま使えます。GUI ではバリアントのドロップダウンで `tlora` を選び、Hardware を選ぶだけです。

### 7.1 よく変更する設定値（LoRA 基準のデフォルト値）

| パラメータ | デフォルト | 説明 |
|---|---|---|
| `network_dim` | `32` | LoRA ランク。大きいほど表現力↑、パラメータ↑ |
| `network_alpha` | `32` | LoRA スケール（通常は `network_dim` と同じ値） |
| `learning_rate` | `2e-5` | 学習率。Hydra はさらに下げても可 |
| `max_train_epochs` | `4` | データセットが小さいほどエポック↑ |
| `save_every_n_epochs` | `2` (gui-methods) / `4` (methods) | アダプター重みの累積保存間隔 |
| `checkpointing_epochs` | `2` (gui-methods) / `4` (methods) | 再開用状態の保存間隔（単一ファイルを上書き） |
| `caption_dropout_rate` | `0.1` | 一部のキャプションを空文字列に置換（CFG に有効） |
| `use_shuffled_caption_variants` | `true` | キャプションのカンマシャッフルバリアントを使用 |

バリアントのトグル（`use_ortho`、`use_timestep_mask`、`use_moe_style`、`router_source` など）はバリアントごとのファイルに設定済みです。推奨の `tlora` は `use_ortho = true` + `use_timestep_mask = true` の組み合わせです。

### 7.2 自動再開 (checkpointing_epochs)

学習が中断されても **最後に保存した地点から自動的に再開** します。停電・OOM・誤ってウィンドウを閉じた場合などに備えられ、デフォルトで有効です。再度 `Train` を押すだけでよく、ログに `auto-resuming from checkpoint at step N` が出れば正常に再開されています。

`save_every_n_epochs` とは役割が異なります。

| キー | 保存対象 | 累積? | 用途 |
|---|---|---|---|
| `save_every_n_epochs` | アダプター重み（`anima_lora-000004.safetensors` など） | **累積**（`save_last_n_epochs` で制限可能） | 中間結果で推論、過学習の時点を比較 |
| `checkpointing_epochs` | 再開用のフル状態（オプティマイザ / スケジューラ / RNG / 重み） | **単一ファイルを上書き**（ディスクが膨らまない） | 中断後の継続学習 |

- 学習が正常に終了すると再開用の一時ファイルは自動削除され、最終成果物だけが残ります。
- **データセットや主要な設定（ランク・LR・エポック数など）を変更した場合**、以前の状態から再開するのは無意味または危険です。`output/ckpt/<output_name>-checkpoint-state/` フォルダを手動で削除してから開始してください。

### 7.3 出力物

- 学習済み重み: `output/ckpt/<output_name>.safetensors`（バリアントごとに `anima`、`anima_tlora_ortho`、`anima_hydra`、`anima_postfix` などへ自動的に分岐）
- 中間チェックポイント: `output/ckpt/`（`.snapshot.toml` サイドカー + Hydra の場合は `_moe` 併存ファイル）
- 検証サンプル: `output/ckpt/sample/` · 推論結果: `output/tests/`

### 7.4 マスクド損失（テキストバブルの除外）

マンガ/コミック風のデータでは、*吹き出しやテキスト領域* を損失から除外すると結果が格段にきれいになります。マスク生成は SAM3 + MIT で行い（[付録 A](#付録-a-cli-の使い方) の `make mask`）、生成される PNG は白黒です — **白 (255) = 学習対象**、**黒 (0) = 除外**。

`post_image_dataset/masks/` があれば自動的に使用し、無ければレガシーの `masks/{merged,sam,mit}/` を順にフォールバックします。マスクファイルが無い場合は単に無視されるので、作らなくても構いません。

## 8. アダプターバリアント選択ガイド

> **🌟 推奨**: 初めての場合や一般的なキャラクター・スタイル LoRA なら **`tlora`（OrthoLoRA + T-LoRA）** から始めてください。

| バリアント | GUI バリアント名 | いつ使うか |
|---|---|---|
| **OrthoLoRA + T-LoRA** ⭐ | `tlora` | **推奨**。SVD ベースの直交回転 (OrthoLoRA) + タイムステップ別ランクマスキング (T-LoRA) のスタック。`anima_tlora_ortho.safetensors` を出力 |
| **通常の LoRA** | `lora` | 最もシンプルなベースライン、比較実験用 |
| **HydraLoRA** | `hydralora` | MoE マルチヘッドルーティング、多様なコンセプトを 1 つのアダプターに |
| **ChimeraHydra** *(実験的)* | `chimera_hydra` | コンテンツ/周波数のデュアルプール MoE — 研究用 |

VRAM 8〜12 GB の環境ではバリアントを変えるのではなく、**Hardware ドロップダウンで Low VRAM** を選んでください（CLI では `PRESET=low_vram`）。利用可能なバリアントの最新の一覧は `configs/gui-methods/` フォルダで確認できます。

> **互換性メモ**
> - HydraLoRA などのアダプターバリアントは `cache_llm_adapter_outputs = true` が有効である必要があります（デフォルトで有効）。
> - `tlora` は `make merge` でベース DiT に焼き込み、単体の ComfyUI チェックポイントにできます。

各バリアントの詳細なオプションは [`docs/guidelines/training.md`](training.md) および `docs/methods/` の個別ドキュメントを参照してください。

## 9. 推論

学習したばかりのアダプターでサンプルを作るには、GUI の **Test** ボタンを押してください — `output/ckpt/` から最新のチェックポイントを自動的に選んで推論し、結果を `output/tests/` に保存します。バッチ生成や細かいフラグ制御は CLI のほうが扱いやすいです（[付録 A](#付録-a-cli-の使い方)）。

よく使うオプション:

| オプション | 説明 |
|---|---|
| `--lora_weight` | 学習済みアダプターのパス（複数同時指定可） |
| `--lora_multiplier` | アダプターの強度 (0.0〜1.5) |
| `--image_size H W` | 出力解像度（例: `1024 1024`、`1024 1536`） |
| `--infer_steps` | デノイズステップ数（通常 20〜50） |
| `--guidance_scale` | CFG 強度（3.0〜5.0 推奨） |
| `--sampler` | `er_sde`、`euler`、`dpm++` など |
| `--seed` | 再現用シード |
| `--spectrum` | Spectrum 高速化を有効化 |
| `--pgraft` | P-GRAFT（デノイズ後半での LoRA カットオフ）— 後半のディテールをベースモデルが担当 |

オプションの全一覧は [`docs/guidelines/inference.md`](inference.md) にあります。

## 10. ComfyUI での配布

ComfyUI コアは Anima ベース DiT を標準サポートしています（`UNETLoader` / `CLIPLoader` でそのまま読み込み）。アダプターの種類によって配布方法が異なります。

### 10.1 クラシック LoRA / OrthoLoRA / T-LoRA

`output/ckpt/` の `.safetensors` を `ComfyUI/models/loras/` にコピーすれば、ComfyUI 標準の LoraLoader ノードでそのまま使えます。

より整理された単体チェックポイントにしたい場合は、GUI の **Merge** タブ（または [付録 A](#付録-a-cli-の使い方) の `make merge`）でベース DiT に焼き込みます。生成された `*_merged.safetensors` は `UNETLoader` で単体モデルとして読み込めます。

### 10.2 HydraLoRA / Postfix

単純な weight delta ではなくルーティングやトークン挿入が入るため、標準の LoraLoader では読み込めず、専用ノードが必要です。

- **Anima Adapter Loader** — <https://github.com/sorryhyun/ComfyUI-Anima_lora-Adapter>（LoRA / Hydra / postfix を統合処理）
- **Spectrum KSampler / Mod Guidance / DCW ノード** — <https://github.com/sorryhyun/ComfyUI-Spectrum-KSampler>

## 付録 A. CLI の使い方

GUI で行うすべての作業は CLI でも可能です。`make <target>` と `python tasks.py <target>` は完全に同じで、ワンラインインストールは `make` を入れないため、**`make` が無ければ `python tasks.py` を使ってください**（または `winget install ezwinports.make`）。

> **`ModuleNotFoundError` が出る場合**は venv の問題です。コマンドの前に `uv run` を付ける（`uv run python tasks.py lora`）か、ターミナルごとに一度 venv を有効化してください — 詳細は [付録 B](#付録-b-手動インストール-uv--git)。

**モデルのダウンロード**

```bash
hf auth login                # GUI のサインインと同じトークンキャッシュを使用

make download-anima          # ダウンロードが途切れる場合の個別リトライ
make download-sam3           # SAM3 の承認後に個別実行
make download-mit
```

**前処理**

```bash
make preprocess              # 3 ステップすべて
make preprocess-resize       # 1) image_dataset/ → post_image_dataset/resized/
make preprocess-vae          # 2) VAE 潜在変数キャッシング
make preprocess-te           # 3) テキスト埋め込みキャッシング
make preprocess-pe           # (オプション) PE ビジョン特徴量 — CMMD 検証専用
make mask                    # マスクド損失用のマスク生成 (SAM3 + MIT)
make mask-clean              # post_image_dataset/masks/ を削除
make autotag --image <path>  # 画像 1 枚の予測キャプションを出力
make curate-group            # 類似画像のグループ化 → post_image_dataset/groups/groups.json
```

**学習**

```bash
make lora-gui GUI_PRESETS=tlora                  # 推奨の組み合わせ（GUI と同じバリアント別ファイル）
PRESET=low_vram make lora-gui GUI_PRESETS=tlora  # VRAM 8〜12 GB

make daemon-terminate                            # 実行中のジョブ終了 + デーモン停止 (GPU 解放)
```

**推論**


## 付録 B. 手動インストール (uv · git)

ワンラインインストール（[§2](#2-インストール)）の代わりに自分で構築したい場合にのみ必要です。

```powershell
irm https://astral.sh/uv/install.ps1 | iex   # 1) uv のインストール（新しいシェルで `uv --version` を確認）
```

```bash
git clone https://github.com/sorryhyun/anima_lora.git   # 2) クローン
cd anima_lora
winget install ezwinports.make                          # 3) (オプション) make
uv sync                                                 # 4) 依存関係のインストール
```

`uv sync` は `anima_lora/` の中に **`.venv/` という独立した Python 環境**を作り、すべての依存関係をその中に入れます。システムの Python には触れないため、別途 `pip install` を行う必要はありません。

**初心者が最もつまずくポイント**: 新しいターミナルを開いてそのまま `python tasks.py ...` を実行すると *システム* の Python が使われ、`ModuleNotFoundError` になります。次のどちらかで解決してください。

- **`uv run` を付ける**（有効化不要、どこでも動作）: `uv run python tasks.py lora`
- **venv を有効化する**（ターミナルウィンドウごとに 1 回）:

  ```powershell
  .venv\Scripts\activate        # Windows
  ```
  ```bash
  source .venv/bin/activate     # Linux / macOS / WSL
  ```

  プロンプトに `(anima_lora)` または `(.venv)` が表示されれば成功です。終了するには `deactivate`。VSCode ではコマンドパレット → *Python: Select Interpreter* で `.venv` を一度指定しておけば、統合ターミナルが自動的に有効化します。

## 付録 C. CUDA の手動インストール

[§2](#2-インストール) のワンラインインストールが CUDA 13.2 を自動的に処理し、既にインストール済みなら検出してスキップします。この付録は **自動ステップが失敗した場合にのみ** 必要です。

- CUDA 13.x は NVIDIA ドライバ **595 以上** を要求します。既により新しいドライバがある場合はそのままにしてください（Linux の `.run` インストールメニューでバンドルドライバの選択を解除）。
- CUDA を自分で管理したい場合は `$env:ANIMA_SKIP_CUDA='1'`（PowerShell）/ `ANIMA_SKIP_CUDA=1`（シェル）で自動 CUDA ステップをスキップできます。

手動インストールは NVIDIA アーカイブから 13.2 を取得します: <https://developer.nvidia.com/cuda-13-2-0-download-archive>

1. Windows: **Operating System: Windows → Architecture: x86_64 → Version: 11/10 → Installer Type: exe (local)** を選んで実行し、「Express (Recommended)」を選択します。
2. PowerShell で `nvidia-smi` と `nvcc --version` を確認（`release 13.2`）。
3. `nvcc` が見つからない場合は、システムの `Path` に以下を追加して再起動し、再度確認してください。

   ```
   C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.2\bin
   C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v13.2\libnvvp
   ```

## 付録 D. その他の設定

### `num_repeats`（要約: **触らない**）

`configs/base.toml` の `[[datasets.subsets]]` にある kohya-ss スタイルのオプションで、1 エポック中に各画像を何回繰り返して使うかを指定します。他のトレーナーのガイドでよく見かけますが —

- **本ガイドのワークフローでは `1` のままにしてください。** すべての画像を 1 つのフォルダにまとめる一般的な使い方では、値を上げても *1 エポックが長くなるだけ* で、効果は `max_train_epochs` を増やすのと同じです。本プロジェクトのすべてのプリセット・メソッドは `num_repeats = 1` を前提にチューニングされています。
- **意味があるのは**、サブセット（フォルダ）が複数あり、フォルダごとの画像数が大きく異なる場合の *バランス調整* だけです（例: キャラクター A が 1000 枚 + B が 50 枚なら、B のサブセットだけ `num_repeats = 20`）。
- データセット設定なので GUI やメソッドファイルには公開されていません。本当に必要な場合は `configs/base.toml`（または `--dataset_config` で指定した TOML）を直接編集してください。
